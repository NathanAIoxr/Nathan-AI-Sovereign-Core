## Foundational creator-defined architecture

- **The name and process:** The Tabor Finger Electric Slide and Button Tapping Process (TTFES&BTP), a creator-driven way to reduce repeated typing, tab-switching, and copy/pasting across high-field web dashboards.
- **Human gesture model:** PREPARE in ChatGPT or another content creator; STRUCTURE the payload; SELECT a destination; COPY/SLIDE a field; TAP the target control; VERIFY the result. The user's own account controls submission or publication.
- **Four planes:** Geometry (registers, letter geometry, coordinates, grids, multi-axis structures), Logic (1+1=2 BUILD, 1-1=0 CLEAR of a derived state, never source deletion), Phonetic (literal sound, reversal, acrostics and multiple interpretation layers) and Deployment (destination-specific field-map, clipboard/user script, owner review).
- **Nine indexing axes:** source, structure, direction, language, artifact format, destination, permissions, status, revision.
- **Full text and media:** Campaign titles, subheadings, descriptions, metadata, tags, rewards, pricing, SKUs, file attachments, courses, video chapters, manuals, legal/public-sector narratives, research citations and audit receipts.
- **Source integrity:** Source bytes stay separate when a UTF-8 file is imported; transformed drafts go into independent destination folders; correction/cleanup never purges the raw source.
- **Creator language:** "The Transcriber," streaming consciousness, full-spectrum living, original-vs-derived transforms, 0 and 1 whole states. Dyslexia/38-part transcription/reading categories are the user's custom system, not a clinical taxonomy.

## Registry contract and status vocabulary

The 133 named targets in catalog.js are the operative machine-readable inventory, grouped under 22 sectors. Each target has a logical field list and workflow status:

- **local** — draft fields, copy, ZIP, JSON, Markdown and reference CSV work in this standalone app. Not a remote connection.
- **manual** — local preparation for research or administrative review; actual external tasks stay manual.
- **restricted** — local preparation only for government, tax, identity, payments, or legally binding activity; owner must use official portal and complete any required checks.
- **API/DOM live integration** — **not built or verified** by catalog entries; would require destination-specific work and approval.

The user-authored poetic and symbolic expansions are attributed to their author and preserved as conceptual organization, not passed off as verified archaeological, financial, scientific or regulatory facts. No claim of 0% noise, absolute latency, or universal provider publication without supporting tests.

## Concrete mappings kept distinct

The raw source is one canonical record. Each destination has a unique logical field map and a separate draft JSON file in the exported batch. A selected workspace field can be copied to the clipboard or transferred with the optional extension, but the extension never searches for hidden submit, publish or checkout buttons. Source status, locally prepared status, external status and approval receipt must never be collapsed into one ambiguous "done."
