### Start on a single computer

From the checked-out repository root:

```sh
node app-factory/nathan-ai/operations/turnaround/network-server.cjs
```

Open `http://127.0.0.1:8787/app-factory/nathan-ai/operations/turnaround/` on that computer.

### Enable local trusted Wi-Fi access

```sh
node app-factory/nathan-ai/operations/turnaround/network-server.cjs --host 0.0.0.0 --lan --port 8787
```

From another device on the **same trusted local network**, open `http://YOUR-LAN-IP:8787/app-factory/nathan-ai/operations/turnaround/` where `YOUR-LAN-IP` is the hosting computer's actual private IP. No API or model token is needed for serving this public static app. Local firewall and router policies still apply. **Do not forward the HTTP port to the public Internet.**

## Defined architecture for future sync (not currently deployed)

A real multi-device data sync system needs more than static hosting. A future consent-based design should require: a user-selected list of peers; strong per-device identity or pairing; authenticated TLS for any private writes; explicit field-by-field permissions; encrypted transport and storage; idempotent record IDs and conflict review; resumable bounded transfers; data caps and opt-in background activity; emergency abort; and independently verified behavior on both iOS and Android. **Removing model API tokens does not justify disabling authentication on a private write service.**

Do not claim Wi-Fi Direct, Bluetooth mesh, 4G/5G failover, distributed supercomputer compute, cross-device ICU Buddy medical operation, peer sync, app-store publication, hardware control, or fully functioning offline PWA in the absence of tested implementations.
