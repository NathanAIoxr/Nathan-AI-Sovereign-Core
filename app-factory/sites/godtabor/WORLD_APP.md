# GODTABOR — IF I WERE GOD, THIS IS HOW I WOULD RUN THE WORLD

**Created for Nathan Tabor · Interactive application v1.0 · November 14, 2026**

## Launch

Open [world.html](world.html) in any modern browser. This is a functional HTML/CSS/JavaScript app, added to the existing GODTABOR franchise alongside [index.html](index.html) and [studio.html](studio.html). No account and no build step required. The franchise homepage links to the app.

## Implemented modules

1. **My World:** world name, authored vision, unbreakable promise; browser-local persistence.
2. **World Laws:** propose, categorize, save and delete personal laws; six fixed core safeguards.
3. **Council & Veto:** submit proposals with impact analysis; mark approved/review/vetoed; reversible personal simulation.
4. **Protect Innocence:** explicit ban on child sexual exploitation, no institutional cover-ups, survivor privacy, independent investigation, reporting links and a copyable charter.
5. **Concordance:** source links into HUMANOID, Nexus, MAS SPIRIT and the Tabor Concordance.
6. **Portable data:** JSON export and validated JSON import with a 1 MB limit. No data leaves the browser via this app.

## Safety by design

- Child sexual abuse and exploitation are unacceptable. No content endorsing abuse or retaliation is intended or supported.
- The text-matching rejection check is **only a lightweight client-side safeguard** and **not** reliable enough to moderate a public service. Do not use it as a production moderation engine.
- No incident reports or children's identifying data are collected or stored by this app.
- NCMEC CyberTipline, RAINN, and emergency service guidance point users to appropriate real-world services. This app is not itself a reporting endpoint.
- No public allegation feed and no automated punishment actions. The Council is a simulation.
- Data is stored in browser localStorage; this is not secure storage for sensitive or confidential information. Exported files are user-controlled and should be protected.

## Next production engineering steps (not deployed)

Authenticated user accounts, server/database sync, durable audit logs, governance review roles, legal/privacy analysis, accessibility testing, professional moderation, and incident-response integration would be necessary for a production multi-user app. Do not represent the current local-first build as a live backend.
