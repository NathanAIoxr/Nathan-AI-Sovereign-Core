# Nathan AI Joy Studio — macro and micro architecture

## Purpose

The platform is a nostalgic, joyous “refrigerator door” for every family, calendar, celebration and scrapbook. The *micro* modules work independently. The *macro* ONE interface unifies them through public, versioned interfaces without replacing source projects.

```
                    NATHAN AI / ONE HUB
                 Navigation · User control
                          |
  +-----------------------+--------------------------+
  |                       |                          |
Fridge Calendar       Zero-Scrap Studio          Word Workshop
EventRecord           DesignDocument             DraftDocument
ICS export            editable Layer[]            phonetic analysis
  |                       |                          |
  +------------ Local Data / Memory Library ---------+
                               |
              Export JSON / HTML / PNG / print
                               |
                 Share via user-owned channels
                               |
              Privacy Shield / Consent & Evidence
                Hash / Compare / Report / Review
                               |
           Future optional, authorized integrations
       Calendar APIs · Mail · External ONE app adapters
```

## Micro schemas

### `EventRecord`
`{ id, date: 'YYYY-MM-DD', title, kind, notes }` — future additions: recurrence rules, attendee consent, notifications, timezone and alarms.

### `DesignDocument`
`{ id, title, theme, updatedAt, layers: Layer[] }`. `Layer` has `id,kind,text,x,y,w,h,size,color,rotate,img?` with positions as percentages and type size as canvas pixels relative to 960×640. The renderer sanitizes inputs. Saved archives use JSON and stable `format` and `version` metadata.

### `DraftDocument`
Currently `{ writing: string }`; future record structure includes writing modes, phonetic/source annotations, language scripts, acrostic constraints, author-selected revision history and translation provenance.

### `ProtectionCase`
Currently `{ id, date, url, desc }`; future workflow uses `{ ownerConsent, platform, sourceUrl, candidateHash, detectionMethod, confidence, humanReview, evidence, noticeStatus }`.

## Holiday and calendar expansion

Theme metadata is extensible. Dynamic lunar/observed religious dates must come from reliable algorithms or explicit user-selected dates. Do not blindly assign moving holidays to fixed dates. Add custom family traditions, anniversaries, graduation dates, school reminders, seasons and local community events.

## Design and distribution reality

- PNG is rendered locally via Canvas and is portable; text wrapping may differ slightly from editable CSS.
- HTML is a standalone static page containing embedded image data; script-free on export.
- `mailto:` opens a draft without attachments. Bulk emailing requires a provider-specific authenticated connector plus consent and rate-limits.
- Print via the browser dialog supports PDF, but PDF is not programmatically generated by this prototype.
- “No scraps” means durable, editable layers in the design model—not a promise that any email client can render arbitrary interactive designs inside an inbox.

## Implementation addendum: playable Joy Game World (v0.2)

The v0.2 code is appended to `app.js`, keeping the original clean project format and its functions. Front-end `#gameView` is additive in `index.html` with independent style rules appended to `styles.css`.

**State shape** (included in the existing `nathan-ai-joy-studio-v1` localStorage key and version-1 backup for backward compatibility):

```json
{
  "game": {
    "xp": 0,
    "rewarded": [],
    "history": [],
    "matchWins": 0,
    "bingo": {"checked": [12], "lines": [], "round": 1},
    "advent": {"entries": {}, "opened": []}
  },
  "magnets": [],
  "consents": []
}
```

- Pure deterministic helpers `bingoLines`, `cleanGame`, `makeMatchDeck` and 25-prompt, 25-task definitions enable Node unit tests.
- All user-provided strings enter DOM via `textContent` or escaped HTML export; no HTML is evaluated from user input. Imported photo source allowlists continue to reject SVG script payloads.
- Memory Match is session-stateful and completed rounds are counted persistently; replaying a round is allowed. Bingo and Advent journals are persistent; game stats are local-only and never transmitted.
- `awardStars` uses a one-time award key for actions such as the first save of a particular project, specific advent days or one bingo line per round. It never claims externally certified completion.
- `archiveCurrentDraft` preserves previous work when replacing the current draft through new-page/preset/game actions. The project library uses a bounded 500-item store, with local browser limits still governing total bytes.
- `renderCalendar` projects annual events into any matching later year while keeping the original event in storage. `createIcs` adds `RRULE:FREQ=YEARLY` on repeated events.
- The permission ledger is not a rights-registration authority. A record is evidence of a local assertion, not a legal ownership determination, authentication or technical takedown.
