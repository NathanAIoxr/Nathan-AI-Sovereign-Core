# TABOR Symmetry Runtime — WILL/WHEEL/WAY × MILL/MHEEL/MAY

**CONTINUE BUILDING.** Additive integration of the software-defined supercomputer, Tabor Chips, digital-hardware conversion system and word rotation families.

## Independent execution modes

- **W engine:** WILL / WHEEL / WAY — nine ordered transitions, including self-identities and bidirectional links.
- **M engine:** MILL / MHEEL / MAY — six-step mirrored handshake, including input refinement, buffer latch and permission.
- **Twins:** WILL↔MILL; WHEEL↔MHEEL; WAY↔MAY.
- **Triplets:** each three-node family operates independently.
- **Unified:** both circuits can run on the same input context, returning separate receipts and a combined completion flag.
- **Extended families:** 3ILL / 3HEEL / 3AY and <<ILL / <<HEEL / <<AY remain independent transformations connected to the wider Tabor graph.

## Mapping to digital hardware

WILL = authorized directive; WHEEL = compute placement and capacity; WAY = network path and routing.
MILL = input refinement; MHEEL = controlled buffer hold and interrupt; MAY = permission, timing and thermal gate.

The simulator's gates are modeled as deterministic software checks; the code does not physically reconfigure FPGA gates or optical MEMS. Such hardware adapters can be added through the universal digital-hardware interface.

## Run modes

`executeCircuit(ninePoint, context)` and `executeCircuit(sixPoint, context)` operate independently.
`runTwinEngines(context)` returns both execution receipts. If a gate fails, the circuit halts with a specific reason.

The implementation uses native TypeScript without third-party runtime dependencies. Source tests are included; compile/test execution and Cloudflare integration remain subsequent build cycles.
