# NATHAN AI — Expansion without collapsing projects

This registry catalogs 182 named capabilities across 8 domains, based on recovered user project context. It is **not** a complete inventory of all historical projects and does **not** assert the capabilities are built.

## Execution contract
1. Preserve the original name, source, ownership, provenance, version, and project identity.
2. Give each app, game, book, website, server, research collection, and agent its own independently testable entry point.
3. Link related modules through Tabor World Hub; never overwrite an independent module with a generic replacement.
4. Follow the Nathan Tabor Way: CLEAR (1-1=0), BUILD (1+1=2), INTEGRATE (1x1=1), VERIFY (1/1=1).
5. Separate cataloged, coded, deployed, HTTP-tested, operational, hardware-installed, and benchmarked statuses.
6. Require explicit operator approval for spending, hardware provisioning, destructive actions, publishing personal records, credential changes, or external outreach.
7. Protect innocence, consent and user sovereignty; keep research evidence separate from interpretation and allegations.
8. Never claim theoretical GPU FLOPS, Bitcoin mining hashrate, agent counts, or quantum claims are measured.
9. CI must validate source modules, secrets hygiene, deployment bindings, mobile compatibility and test receipts.
10. Each module must have acceptance criteria, an owner/agent assignment, dependencies, provenance, a verification receipt, and a next implementation step.
