# Shared app and game requirements

Use the app-factory/shared/material-worlds modules and app-factory/shared/material-worlds/STANDARD.md for presentation work. Keep each app's theme and authored identity distinct. Do not overwrite existing game save keys, progress, source archives, character markings, or independent modules.

Free access: no paid tokens, premium currency, gacha, paid retries, session-energy limits, purchase gates, or mandatory waiting for refills. Tactical charge is local strategy, not a monetization path. Advanced game rules are consumer opt-in; classic behavior remains available.

Use truthful feature availability. Do not label a local rehearsal as a live remote war, a heuristic as a neural network, base-12 formatting as a performance optimization, or a seeded client as server-verified. See app-factory/shared/material-worlds/COMMUNITY_AND_ROLLOUT.md for built versus service-dependent features.

Respect reduced motion, device limits, accessible element labels, and optional ambient behavior. No location, biometric, camera, microphone, or external weather collection by default. Use only existing authorized data access.

For public repositories, never copy private library builds, research/source archives, user files, or personal media into public Git. General reusable code and authorized specifications may be synchronized. Run engine and community tests before integration; separate visual QA from logic tests.
